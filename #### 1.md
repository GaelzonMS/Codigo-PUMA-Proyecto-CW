#### 1. INFORMACIÓN INICIAL

- **Autor:** Equipo de Desarrollo Front/Back 
- **Título del proyecto:** Letterbooks - Red social de registro y reseña literaria.
- **Fecha de inicio:** 1 de mayo de 2026
    

#### 2. RESUMEN DEL PROYECTO, METAS Y OBJETIVOS

- **Resumen:** Letterbooks es una aplicación web que permite a los lectores llevar un bitácora visual de los libros que han leído, los que desean leer, y compartir reseñas y calificaciones con una comunidad de entusiastas de la literatura.
    
- **Metas:**
    - Lanzar el producto funcional en 1 mes.
    - Lograr una interfaz intuitiva donde registrar un libro tome menos de 3 clics.
        
- **Objetivos:**
    - Integrar una API externa para poblar automáticamente la base de datos de libros.
    - Crear un sistema de calificación y reseñas.

#### 3. PÚBLICO OBJETIVO (UX)
- Lectores ávidos (16-45 años) que buscan una alternativa visual y moderna a plataformas anticuadas. Valoran el diseño limpio, la velocidad y la interacción social sin fricciones.

#### 4. PROPÓSITO Y ALCANCE

- **En alcance (Entregables):**
    - Sistema de autenticación y perfiles de usuario.
    - Buscador de libros, autores, editoriales y géneros literarios.
    - Posibilidad de dejar reseñas respecto a libros y comentar las reseñas.
    - Edición de perfil, así como estadísticas de reseñas que te han gustado, reseñas que has hecho, etc...
- **Fuera de alcance:**
    - Lectura de e-books dentro de la plataforma.
    - Venta de libros o integración de pasarelas de pago.
    - Aplicación móvil nativa (se entregará solo web responsiva).

#### 5. ESPECIFICACIONES FUNCIONALES

| **Módulo**     | **Descripción**                                                              | **Criterio de Aceptación**                                                      |
| -------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Autenticación  | El usuario podrá registrarse usando email y contraseña.                      | El sistema debe enviar un correo de verificación exitoso.                       |
| Búsqueda       | El usuario podrá buscar libros por título, autor o ISBN.                     | La búsqueda debe mostrar resultados predictivos al escribir 3 caracteres.       |
| Registro (Log) | El usuario podrá calificar un libro del 1 al 5.                              | La calificación debe guardarse en el perfil y actualizar el promedio del libro. |


#### 6. REQUISITOS NO FUNCIONALES

| **Categoría**     | **Requisito**                                                      |
| ----------------- | ------------------------------------------------------------------ |
| **Rendimiento**   | Tiempo de carga inicial rápido (LCP).                              |
| **Accesibilidad** | La web debe ser navegable mediante teclado y lectores de pantalla. |
| **Seguridad**     | Las contraseñas deben estar encriptadas.                           |

#### 7. ARQUITECTURA DE LA INFORMACIÓN Y UX

- **Patrón de Navegación:** Barra de navegación superior fija (Sticky Navbar) con: Inicio, Explorar, Biblioteca, Mi Perfil.
- **Diseño Visual:** Se permitira.

#### 8. ESPECIFICACIONES TÉCNICAS

- **Frontend:** React.js para un renderizado rápido. Tailwind CSS para el sistema de diseño responsivo.
- **Backend:** Springboot con Java para gestionar la lógica de negocio y las peticiones a APIs externas.
- **Base de Datos:** MariaDB para relacionar usuarios, libros, reseñas y seguidores de manera estructurada.
